# API v1 — Breaking change: география удалена (только Ашхабад)

**Кому:** разработчикам мобильных приложений (Client + Master)
**Статус:** изменения уже в `main`, релиз бэкенда нужно согласовать с выкаткой приложений

---

## Что случилось

Сервис изначально проектировался под весь Туркменистан: была иерархия **велаят → город**, и
мастера, клиенты и заказы были привязаны к городу (`city_id`). Заказчик решил, что сервис
обслуживает **только Ашхабад**, поэтому вся география удалена из БД, админки и API.

Города, велаяты и районы больше не существуют — ни как справочники, ни как поле.
Адрес заказа полностью описывается связкой **`client_address` + `client_lat` / `client_lng`**,
которая работала и раньше и не менялась.

---

## Насколько это ломает приложения

| Приложение | Степень |
|---|---|
| **Client** | Ломается: пропали 3 эндпоинта справочников и поля `city` / `city_id` в ответах |
| **Master** | Минимально: только `city` из ответа `GET /master/me`. Заказы (`MasterOrderResource`) города никогда не отдавали |

> **Главный риск — Dart null-safety.** Если модель объявлена как `final City city;` (не nullable)
> или парсится через `json['city']['name']`, приложение **упадёт при парсинге**, а не покажет
> пустое поле. Это самое важное, что нужно проверить.

---

## 1. Удалённые эндпоинты (отдают `404`)

```
GET /api/v1/client/oblasts
GET /api/v1/client/regions
GET /api/v1/client/cities
```

Замены нет — выбор города убирается из UI целиком (экран регистрации, форма заказа, фильтры).

---

## 2. Поля запросов

Убраны из валидации:

| Эндпоинт | Убрано |
|---|---|
| `POST /api/v1/client/auth/complete-registration` | `city_id` (было `required`) |
| `PATCH /api/v1/client/me` | `city_id` |
| `POST /api/v1/client/orders` | `city_id` (было `required`) |
| `PATCH /api/v1/client/orders/{id}` | `city_id` |

**Хорошая новость:** если старая сборка всё ещё шлёт `city_id`, ошибки `422` не будет — Laravel
берёт только валидированные ключи, лишние молча игнорируются. То есть **отправка `city_id` не
сломает старые сборки**, ломается только чтение ответов и запросы к удалённым справочникам.

Раньше `complete-registration` требовал `city_id`, теперь достаточно одного `name`:

```json
{ "name": "Merdan Annagurdow" }
```

---

## 3. Поля ответов

### Клиент — `ClientProfileResource`

Возвращается в `verify-otp` (ключ `client`), `complete-registration` (ключ `client`),
`GET /client/me`, `PATCH /client/me`.

```diff
  {
    "id": 1,
    "name": "Merdan Annagurdow",
    "phone": "+99361111222",
-   "city_id": 1,
-   "city": { "id": 1, "name": "Ашхабад" },
    "created_at": "2026-08-11 10:00:00"
  }
```

### Клиент — `ClientOrderResource`

Возвращается в `GET /client/orders`, `GET /client/orders/{id}`, create / update / cancel.

```diff
  {
    "id": 10,
    "status": "pending",
    "client_address": "ул. Андалиб, 12",
    "client_lat": "37.9523210",
    "client_lng": "58.3823450",
-   "city": { "id": 1, "name": "Ашхабад" },
    "category": { "id": 7, "name": "Сантехника" },
    ...
  }
```

### Мастер — `MasterProfileResource`

Возвращается в `verify-otp` (ключ `master`), `GET /master/me`, `PATCH /master/availability`.

```diff
  {
    "id": 3,
    "name": "Мерген Аннамырадов",
    "phone": "+99362100000",
    "balance": 120.5,
-   "city": { "id": 1, "name": "Ашхабад" },
    "categories": [ { "id": 7, "name": "Сантехника" } ]
  }
```

`MasterOrderResource` **не менялся** — он и раньше отдавал только `address` / `latitude` / `longitude`.

---

## 4. Broadcasting

Публичный канал позиций мастеров переименован:

```diff
- masters-map.{cityId}
+ masters-map
```

Это канал **только для админ-панели**. Приложение мастера на него не подписывается (см.
[MASTER_APP_SPEC.md](MASTER_APP_SPEC.md)), приватные каналы `client.{id}` и `master.{id}`
не менялись.

- [ ] Убрать вызовы `/client/oblasts`, `/client/regions`, `/client/cities` и их модели
- [ ] Убрать выбор велаята/города с экрана регистрации и из формы создания заказа

- [ ] **Убрать `city` / `city_id` из моделей ответов** — иначе падение парсинга на non-nullable полях
- [ ] Проверить, что нигде не показывается город в карточке заказа и в профиле

**Master app**
- [ ] Убрать `city` из модели профиля мастера
- [ ] Больше ничего — экраны заказов не затронуты

## 6. Что уточнить у бэкенда

Если что-то из этого важно для UI — скажите, доработаем:

1. Нужно ли где-то показывать «Ашхабад» как статичную подпись, или город убирается из интерфейса совсем?
2. Нужен ли переходный период, когда старые эндпоинты справочников отдают пустой массив вместо `404`? Сейчас их нет совсем — если у вас много старых сборок в проде, это стоит обсудить **до** релиза бэкенда.
3. Планируется ли позже деление Ашхабада на этрапы (районы)? Если да, лучше заложить это в модели сейчас, чтобы не делать вторую миграцию.
